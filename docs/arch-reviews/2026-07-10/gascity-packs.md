# Architecture review — gascity-packs (/home/ds/gascity-packs-main)

Date: 2026-07-10 · HEAD f9b70a5 (2026-06-17) · read-only

## Executive summary

Monorepo of 14 Gas City packs (prompt/formula content + 6 independent Go modules + Python service scripts) with a genuinely strong formula-contract layer: `build-base` + `extends` gives five methodology packs a clean, vars-only override surface. The structural debt concentrates in four places: (1) the committed LikeC4 architecture model documents packs that no longer exist in this repo and its drift guard was made non-blocking instead of the model being fixed (47 dead links); (2) supporting a pack requires hand-editing ~7 registration points (a 4.5K-line test file, two gate tables in a 2.8K-line script, two CI matrices, README tables, registry) even though the machine-readable metadata already exists in each `pack.toml`; (3) the repo-wide conformance suite lives inside the shipped `gascity` pack and reaches into sibling packs, so released pack bytes carry repo-layout-coupled tests; (4) two families of runtime kernels — Slack HMAC/dedup (3 Go copies) and the intake service state/config kernel (discord 4.9K-line vs github 1.3K-line Python commons) — are re-hand-rolled per pack with no sync enforcement, unlike the claim-protocol fragment which already has the right pattern (canonical copy + byte-identity test + symlinks).

## Architecture map (how it is actually structured)

- **Content packs, one per top-level dir with `pack.toml` (schema 2).** Each pack is self-contained because consumers import by git subpath (`…gascity-packs.git//bmad`) — a pack cannot reference `../sibling` files at runtime. This self-containment force explains most duplication below; any fix must respect it.
- **Contract layer (`gascity/`):** `build-base.formula.toml` defines the virtual full-lifecycle contract (stage names, launch vars, `[metadata.gc.methodology]` vocabulary). Four methodology packs (bmad, compound-engineering, superpowers, gstack) each import gascity as `gc` and override via `extends = ["build-base"|"planning-base"|"fix-loop-base"|…]` with vars-only diffs (e.g. `bmad/formulas/bmad-fix-loop.formula.toml` is 22 lines against a 66-line base). This is the repo's best structure.
- **Runtime packs:** slack-mini/channel/full (three-tier Go adapters, separate modules, deliberately non-stacking per `docs/design/slack-pack-tiering.md`), discord + github (Python `proxy_process` intake services), runtime-cloudflare (RPP runtime module), gastown (orchestration roles).
- **Distribution: three parallel channels with different pinning semantics.** (a) Go embed for the gc binary — `embed.go:16` embeds only `gastown` + `gascity`; (b) `registry.toml` content-addressed releases — 8 packs; (c) raw git subpath — everything else. bmad/compound-engineering/superpowers/gstack/runtime-cloudflare have **no registry entries** despite the README marketing them as first-class.
- **Verification:** repo CI (`.github/workflows/ci.yml`) hand-enumerates each pack's test paths; cross-pack contract enforcement lives in `gascity/tests/test_formula_assets.py` (4,515 lines) + `test_derived_pack_compatibility.py` (508 lines, imports the former as a module); model-backed gates in `scripts/gascity_pack_inference_gate.py` (2,849 lines) with their own per-pack spec tables.

## Major strengths (protect these)

- **`build-base` contract + `extends` lattice.** Methodology packs override defaults, not structure. Switching methodology is a one-word formula-name change; this is real leverage and should be the template for any new pack family.
- **Claim-protocol fragment sync pattern.** `gc-role-worker.template.md`: 1 canonical (`gascity/roles/prompts/shared/gc-role-worker.md.tmpl`), 7 real copies (one per pack, forced by self-containment), 59 within-pack symlinks, byte-identity enforced by `test_derived_pack_compatibility.py:331` (`test_agent_prompts_embed_shared_claim_protocol`). Drift is impossible without a red test. This exact pattern is the cheap fix for findings 4 and 5.
- **Content-addressed registry releases** with stamp/withdraw tooling (`Makefile` targets driving `gc pack release stamp`) and a registry-driven compat smoke.
- **Deliberate, documented tier design** for Slack (`docs/design/slack-pack-tiering.md` explicitly decided not to extract shared code — the memo states the force; finding 4 argues only the security kernel warrants an exception).

## Ranked findings (leverage ÷ effort, risk-discounted)

### 1. Architecture model is drifted and its guard was silenced instead of fixed
- **Evidence:** `architecture/model.c4:77-104` links `../slack-pack/…` (renamed `slack-full`); the model's scope is five packs of which two (`pr-pipeline`, `pr-review`) do not exist in this repo. Running the guard: `node architecture/site/check-links.mjs` → **47 dead source links**. Latest commit `f9b70a5` ("make architecture drift guard report-only") disabled the gate rather than repairing the model. README's "Layout" section also describes `all/` rollup group dirs that no longer exist (`README.md:143-145`).
- **Why it matters:** architecture-as-code that lies is negative-value documentation — every reader must now verify each box against the tree, and the report-only guard institutionalizes further drift. The guard already exists; re-arming it is the whole point of having it.
- **Fix shape:** rename `slack-pack` → `slack-full` in `model.c4`, either import the pr-pipeline/pr-review packs into the repo or cut them from the model (tag `#external`), flip the workflow step back to blocking.
- **Effort:** S. **Risk:** minimal, fully reversible.

### 2. Pack registration surface: ~7 hand-edited points per supported pack, duplicating metadata the packs already declare
- **Evidence:** adding/supporting a methodology pack touches (a) `gascity/tests/test_formula_assets.py:290` `THIRD_PARTY_BUILD_PACKS` — including the vendored upstream URL+commit, which is provenance data living in a test file; (b) `scripts/gascity_pack_inference_gate.py:518` `make_pack_specs()` **and** the second per-pack expansion table at `:159`; (c) `.github/workflows/gascity-pack-inference.yml:44` choice list; (d) `.github/workflows/supported-pack-nightly.yml:46,123,127` choice list + matrix; (e) `.github/workflows/ci.yml:41` hardcoded pytest path list; (f) two README tables; (g) `registry.toml`. Meanwhile each pack already carries `[metadata.gc.methodology]` (e.g. `bmad/formulas/bmad-build.formula.toml:18`) and formula defaults that encode most of the same facts.
- **Why it matters:** this is the axis the repo grows along — the README's whole pitch is "add another methodology pack". Every new pack pays the 7-point tax and every divergence between the tables is a silent gap (a pack in CI but not the gate, or vice versa). One derived catalog turns N registration points into 1.
- **Fix shape:** a single machine-readable catalog (extend `registry.toml` or a `packs.toml` next to it; vendored-upstream provenance moves to a `vendor.toml` per pack). Tests, gate specs, and workflow matrices read/derive from it (workflows via a generation check or a `discover` step). `test_derived_pack_compatibility.py` already derives from `test_formula_assets` constants — extend that direction to the source of truth instead of a test module.
- **Effort:** M. **Risk:** low-medium — mechanical migration, verifiable by diffing derived tables against today's hardcoded ones.

### 3. Repo-level conformance suite ships inside the `gascity` pack and is coupled to monorepo layout
- **Evidence:** `gascity/tests/test_derived_pack_compatibility.py:22` `PACKS_ROOT = pathlib.Path(__file__).resolve().parents[2]` then reaches into `../bmad`, `../superpowers`, etc.; `test_formula_assets.py` (4,515 lines) is imported as a library by the sibling test. Registry releases hash all tracked files under the pack path (README.md:218-219, and gastown 0.1.3's release note confirms tests ship to consumers), so consumers of the `gascity` release receive cross-pack tests that can only pass inside this monorepo. Contract *data* (stage anchors, forbidden dispatch phrases, metadata vocabulary) is embedded in test code.
- **Why it matters:** layering violation with compounding cost: the shipped artifact carries dead repo-coupled weight; the contract has no home a non-Python consumer (or the gate script) can read; and the 4.5K-line test file is the choke point every pack PR must be understood against. Splitting data from assertions is also the enabler for finding 2.
- **Fix shape:** move cross-pack conformance to top-level `tests/` (repo scope), leave only pack-local checks in `gascity/tests/`; extract contract constants (BUILD_BASE_STEPS, vocabulary, forbidden phrases) into a checked-in data file both tests and the inference gate load.
- **Effort:** M. **Risk:** low — test moves are reversible; release hash for gascity changes (needs a routine release bump).

### 4. Slack security kernel (HMAC verify, dedup, fail-closed semantics) triplicated across tiers with no sync enforcement
- **Evidence:** `verifySlackSignature` implemented three times: `slack-mini/adapter/main.go:434`, `slack-channel/adapter/signature.go:17`, `slack-full/adapter/main.go:1966` (plus `verifySlackSignatureMulti` only in full). Three separate Go modules (`gc-slack-mini-adapter`, `gc-slack-channel-adapter`, `gc-slack-adapter`); zero shared files by content between channel and full despite shared filenames (`interactions.go`: 38 vs 867 lines). `slack-full/adapter/main.go` is 3,472 lines. The tiering memo consciously declined extraction — for features, that is defensible; for the request-authentication kernel it is not.
- **Why it matters:** a signature-verification or replay-dedup bug is a security patch that must land three times, in three modules, with three test suites, and nothing detects when one copy drifts (e.g. a fail-open regression in one tier only). Pack self-containment forbids a `replace ../shared` module — but it does not forbid the proven copy+byte-identity-test pattern already used for `gc-role-worker`.
- **Fix shape:** minimal — carve `signature.go`/`dedup.go` into identical files in all three adapters and add a repo-level test asserting byte-equality (mirroring `test_agent_prompts_embed_shared_claim_protocol`). Larger option (shared Go module + vendor-sync script) only if the kernel keeps growing.
- **Effort:** S (sync-test route) / M (shared module). **Risk:** low for sync-test; the memo's independence constraint is preserved.

### 5. Intake-service kernel re-hand-rolled between discord and github packs; discord common is a 4.9K-line monolith
- **Evidence:** `discord/scripts/discord_intake_common.py` (4,926 lines, 258 defs) vs `github/scripts/github_intake_common.py` (1,296 lines, 95 defs) share 35 identically-named kernel functions (`atomic_write_json`, `state_root`, `ensure_layout`, `save_request`/`load_request`, `save_workflow_link`, `published_services_dir`, `redact_config`, …) — the state-layout/config-lifecycle/request-persistence/service-publication kernel of a gc `proxy_process` intake. `discord_intake_service.py` (1,368) + `discord_gateway_service.py` (2,323) sit on top.
- **Why it matters:** this is the template every future intake pack (Telegram, Matrix, email…) will copy; the copies have already diverged in shape (discord 4x github), so kernel fixes (atomicity, redaction, lock handling) no longer transplant cleanly. The 4.9K-line common file is also the single hardest-to-review surface in the repo.
- **Fix shape:** define the kernel subset explicitly, converge the two implementations to identical kernel modules (`*_intake_kernel.py`), enforce with a byte-identity or AST-equality repo test — same pattern as findings above. Splitting discord's common into focused modules can ride along but is secondary.
- **Effort:** M. **Risk:** medium — behavioral convergence needs the existing per-pack test suites as the net (they are decent: `discord/tests/`, `github/tests/`).

### 6. Distribution channels disagree on coverage and pinning; methodology packs are unreleased
- **Evidence:** `embed.go:16` embeds gastown+gascity only; `registry.toml` releases 8 packs (bmad, compound-engineering, superpowers, gstack, runtime-cloudflare absent); README step 6 tells users to `gc import add …//bmad` — an unpinned-by-registry path for exactly the packs positioned as the headline feature. Existing pins also lag: discord/github/slack-* pinned at `788b6e8` (2026-06-01) while `github/` has 4 commits since. `pack_release_compat.py` gating is registry-driven, so unregistered packs are outside the release compat gate entirely (the inference gate covers them from source, but nothing gates a *released* coordinate because none exists).
- **Why it matters:** consumers of the five build packs get whatever `main` holds; the compat machinery the repo invested in (registry smoke, nightly) cannot protect the packs users are steered toward. One decision (register methodology packs) brings them under the existing gates for near-zero new machinery.
- **Fix shape:** stamp initial registry releases for bmad/compound-engineering/superpowers/gstack (+ runtime-cloudflare when RPP lands); add a doc table stating which channel serves which pack and why embed is gastown+gascity-only.
- **Effort:** S-M (process + a few stamps). **Risk:** low; withdraw path exists.

## Leave unchanged

- **Formula lattice in `gascity/formulas/`** (`build-from-*` base/concrete pairs, `implement` → `do-work` → `implementation-base`): files are small (21-138 lines) and genuinely distinct; no duplication problem despite the file count.
- **Slack tier separation itself** — the "pick exactly one tier" design and non-stacking packs are documented, deliberate, and correct for the import model. Only the security kernel (finding 4) warrants sharing.
- **`scripts/gascity_pack_inference_gate.py`'s size** (2,849 lines) — it is an end-to-end city-builder harness; splitting it is cosmetic unless finding 2 extracts its spec tables, after which the remainder is plumbing.
- **`registry.toml` release-history-as-TOML** — verbose but content-addressed and tool-stamped; fine.
- **Vendored upstream trees (`*/vendor/`)** — correctly treated as source material, guarded by the forbidden-dispatch-phrase tests.
