## 1. Project shape

EnterpriseBench is a **benchmark** (Python) that measures how well coding agents **find and comprehend the right code across large, multi-repo enterprise codebases** — not code generation. It is the evolution of the unpublished **CodeScaleBench (CSB, 275 tasks)**; CSB tasks carry forward ("fix, extend, don't rebuild") and 178 sg-evals mirrors come from CSB. **Sourcegraph MCP is the first-class showcase, but tool access is a controlled independent variable** (baseline / mcp_only / hybrid) — the whole point is to measure whether MCP-based navigation lifts agent performance. The project is on a **publication track**: `paper/paper.md` (hand-written, 22K), `RELEASE.md`, `docs/internal/scaffold_enterprisebench_publish.md`, a LikeC4 architecture page auto-deployed to GitHub Pages.

- **Scale:** 112 active tasks across 10 task types in 7 workflow suites (dependency_management 27, customer_escalation 24, technical_debt 19, feature_delivery 18, incident_response 12, platform_engineering 10, security_operations 2); 28 archived single-repo tasks under `benchmarks/_archived/`. 50.9% of tasks are strict multi-repo (dual+tri+multi); repos are **real OSS only**, pinned by SHA/tag, connected by real dependency chains (e.g. `grpc-go → etcd → kubernetes`).
- **The central deliverable, stated in the project's own words:** "a verification pipeline that survives a skeptic" (.gc-reports/audit-2026-07-06.md:19). Everything load-bearing hangs off **scoring integrity** — a benchmark is only worth its numbers, and the numbers are only worth the scorer's trustworthiness.
- **Two-axis verification model.** (a) **Checkpoint scoring:** 2–5 graduated checkpoints per task for partial credit, each a bash verifier that prints `{"score": 0-1}`. (b) **Artifact validation:** `lib/eb_verify/` — a plugin registry of 9 always-on artifact validators (answer, code_patch, config, incident_report, runbook, security_assessment, reproduction_script, topological_order, call_graph) + a conditional 10th (fact_triples). Ground truth is **layered**: deterministic grep verifiers (Tier 1), an LLM curator/judge that acts as a score _ceiling_ (Tier 2, `min(grep, judge)`), and `solve_verify.py` structural AST verification (Tier 3).
- **Execution model:** each task runs in a per-task Docker sandbox with its repos cloned into `/workspace/{repo-name}/`; a Claude Code agent runs headless against `instruction.md`; artifacts (canonical `agent_output/answer.json`, plus reports) are scored by an in-container `test.sh`. Runs are partitioned `results/runs/<task_id>/<mode>/rep<N>/`.
- **Who runs it:** effectively a **solo human maintainer (Stephanie / sjarmak, 310 of 311 commits) plus a Gas City agent fleet** — an EnterpriseBench PL (`enterprisebench-pl-gc-454418`) and pool workers drive the repo via beads and worktrees. The "retiring fellow" here is the accumulated _scoring-integrity discipline_ held across Stephanie's rulings, the weekly `.gc-reports` audits, and ~40 `fix/eb-*` branches — knowledge that lives in bead threads and branch names, not in the 50-commit squashed `main`.
- **Docs of record:** `docs/ARCHITECTURE.md`, `docs/internal/PRD.md`, `docs/TASK_TYPE_PRD.md` (10 task types with MCP-signal ratings), `docs/TASK_AUTHORING_GUIDE.md`, `docs/CONVERGENCE_REPORT*.md` (design from structured debate), plus `docs/qa/` audit verdicts and `docs/RUN_PROMOTION.md`.

## 2. Build / test / CI reality

Everyday gates: **CI (`.github/workflows/ci.yml`, Python 3.12) is the real bar**, and it does more than `make test`. CI runs: `pip install -e lib/` → `pytest tests/ -v --tb=short -m "not network and not docker"` → `scripts/audit_consistency.py` → `bash -n` on every non-archived `benchmarks/**/*.sh`. Task-authoring gate: `make verify` = `verify-mix` (task_mix_validator) + `verify-tasks` (validate_tasks_preflight) + `verify-crnt` (Cross-Repo Necessity Test). Two more workflows: `likec4-pages.yml` (architecture page, path-gated on `architecture/**`) and `staleness-check.yml` (weekly + on `benchmarks/`/`configs/` PRs).

**Verified traps for a Sonnet-class newcomer:**

1. **`import eb_verify` fails until you `pip install -e lib/`.** The package is not on the default path; a bare `python3 -c "import eb_verify"` gives `ModuleNotFoundError`. CI and the checked-in `venv/` both install it editable (verified: `venv/bin/python` imports it fine).
2. **`make test` is NOT the CI gate.** `make test` runs only `pytest lib/eb_verify -q`; CI runs the whole `tests/` tree (3756 tests collected this session; README's "779+" is stale). Passing `make test` locally ≠ green CI.
3. **The `fact_triples` validator self-disables when numpy/scikit-learn are absent** — it registers inside a `try/except ImportError` and emits a `RuntimeWarning`; `get_validator("fact_triples")` then returns `None` and the runner reports "No validator registered." A dependency-free sandbox silently loses that validator.
4. **Two test modules fail collection today** (verified): `tests/eb_metrics/test_trace_quality_adapter.py` (`ModuleNotFoundError: No module named 'eb_metrics'`) and `tests/test_verifier_mutation.py` (`from verifier_mutation_test import ...`) — both `sys.path`/packaging gaps. CI's marker filter does not exclude them, so this is either masked by the editable install or a latent red.
5. **pytest markers gate whole classes:** `network`, `docker`, `security` (see `tests/conftest.py`, `tests/security/`). `pytest tests/` without `-m "not network and not docker"` will try to build images and hit the network.
6. **There is no lint/type gate wired into CI** (no ruff/mypy step in ci.yml) despite `.ruff_cache/` and `.mypy_cache/` on disk — those are developer-local, not enforced.
7. **`scripts/audit_consistency.py` is a real merge blocker** (task-consistency audit) and runs after tests in CI; task edits that pass schema can still fail here.

Analysis/paper pipeline (Makefile): `make analyze` (score engine → `results/analysis/score_analysis.json`, always re-scans raw runs) → `make charts` → `make report` → `make paper-figures` (the one command that regenerates every figure into `paper/figures/`; `paper.md` itself is hand-written). `make clean` removes analysis artifacts but never raw runs.

## 3. Git archaeology — lessons that would die with the fellow

`main` is **squash-merged** (50 commits); the real history lives in **~40 `fix/eb-*` / `audit/eb-*` branches** (51 refs total) and in the bead store. Reading the branch names + the latest deep-audit is the only way to reconstruct the fights.

- **The dominant failure class, by a wide margin, is scorer trust-boundary / silent-misscore.** One invariant — _a score is valid only if the pristine verifier ran on real agent output; any infra/verifier/judge failure must surface as `verifier_infra_error`, never a `0.0` or an inflated grep score_ — is **enforced inconsistently in ~6 places**, and each site got it subtly wrong in a different way. The chronicle (each a branch/bead):
  - `hktt`/`pt0n` — **docker-cp dropped the `eb_verify` package dir** (copying a directory to a non-existent dest copies its _contents_), so `python3 -m eb_verify` hit `ModuleNotFoundError` and was scored a silent `0.0`; **contaminated 5 published refactor-orchestration runs.** Fixed by `mkdir -p` before `docker cp` (commit 16280cf).
  - `s58f` — unreadable `instruction.md` (swallowed chown) → agent never starts → recorded as fake `success=True, num_turns=0, score=0.0`. Fixed with a fail-loud `_assert_agent_readable` pre-agent gate.
  - `c7wb` — MCP pre-flight failure let a run proceed "degraded" (no working MCP) and be recorded as a real `mcp_only` measurement, corrupting the MCP-vs-baseline arm. Made a **hard gate** (commits 9832487, daca3cc).
  - `wbsq` — JSON-injection into scoring, including an **RCE-via-`awk`** PoC. `7jpm` — agent rewrites `test.sh`/verifiers in its writable workspace (no pristine re-copy/checksum). `pakh`/`dec-f5g` — the whole **grounded-citation gate** (containment bypass, unconditional gate).
  - The **2026-07-06 deep-audit found 3 MORE of the same class live on `main` HEAD** (`apfp` bead): `_run_scoring` persists a broken `test.sh` as a legit `0.0` (run_task.py:801-818); `_apply_llm_judge` reverts to un-capped grep scores on any judge failure (871-947); `code_patch.validate` collapses any git error into a false "no changes" `0.0` (code_patch.py:32,49).
- **Two scorers exist and the tested one is dead from production's POV** (`cdzi`, audit finding #5). `lib/eb_verify/runner.py::CheckpointRunner.run_all()` (weight-normalized, honors checkpoint weights, has the tests) is invoked only by `cli.py` and `tests/*`. **Production scoring is `scripts/orchestration/run_task.py` + the in-container `scripts/sandbox/test_runner.sh`**, which is **equal-weighted** (per-checkpoint `weight` needs a `.meta` sidecar that `run_task` never emits; declared `task.toml` weights are authoring metadata only). Branch `3psg/document-equal-weighting` documents exactly this. A cap/weight change landed in the library path silently misses production.
- **Deletions / retirements:** 3 coding-ability tasks cut via rfc-dag (9fa129f); single-repo retirement (28 tasks → `_archived/`); stale Phase-1 artifacts and completed one-shot worktrees swept (ca36279, 753c836). No `git revert` commits (squash workflow hides them), but the bead thread records back-outs — e.g. `apfp` scoring fix **backed out of the broken mol-focus-review formula** and handed to the mayor for direct dispatch.
- **Churn hotspots = the fragile core:** `scripts/orchestration/run_task.py` (42 touches, 2016 lines — 2.5x the house 800 max; `run_task()` 338 lines, `_configure_mcp()` 157), `scripts/run_benchmark.py` (10), `schemas/task.schema.json` (9), `configs/sg_indexing_list.json` (9), and a long tail of individual `task.toml` files (grading-keyword relaxation per solve-verification). The audit is explicit that run_task.py's _size is why_ the silent-fallback bugs slid through review.
- **The parting architectural bets (recent feat commits):** the **scorer_guard consolidation** (one `scorer_guard(agent_output, verifier_result) -> Score | InfraError` + a `tests/integrity/` adversarial corpus wired into CI — the audit's "smartest addition"); the **grounded-citation gate** + `fact_triples`/`fact_coverage` comprehension verifiers (verbatim-evidence-span groundedness, TF-IDF semantic recall); **deterministic KG-based cross-repo task mining** (60186e6, d5bf64e); and single-source-of-truth extraction for **sg-evals mirror naming** (`scripts/infra/mirror_naming.py`, after the formula drifted into 5 copies).

## 6. Knowledge gaps a Sonnet-class newcomer falls into

Ranked by expected damage: (1) **not knowing which scorer is production** — editing `CheckpointRunner`/`scoring.py` (weighted, tested) believing it changes real scores, when production is `run_task.py` + `test_runner.sh` (equal-weighted); (2) **introducing a silent-misscore** — any `except: return 0.0` / bare `continue` / swallowed infra error that records a fake score instead of `verifier_infra_error` (the entire dominant bug class); (3) trusting `make test` as the gate, or forgetting `pip install -e lib/`; (4) misreading intentional designs as bugs — **mcp_only still clones repos locally** (run_task always builds the standard Dockerfile; the empty-workspace `Dockerfile.sg_only` is generated but unused; the mode is enforced by prompt + 0-MCP-call invalidation), `_indexed` is **hardcoded False** for every mirror so `mirrors_indexed` preflight warns by design, `_check_disk_space` fails open, `resume` is an accepted `--session-type` that is a no-op skip; (5) the **docker-cp directory-semantics** trap (`mkdir -p` before `docker cp` is load-bearing, not redundant); (6) breaking the **sg-evals mirror naming** invariant (must use `scripts/infra/mirror_naming.py::derive_mirror_name`; a `<sha>~1` rev is unrepresentable as a GitHub name — resolve to a concrete SHA first); (7) letting `fact_triples`/`fact_coverage` TF-IDF scoring touch adversarial grading (word-order-blind: reversed relations score ~1.0 — cooperative recall only); (8) authoring a multi-repo task that fails **CRNT** (the answer must genuinely require crossing repos); (9) not realizing scoring-path changes are **HALT-branch-ready** — they need Stephanie's approval and must ship tests, and right now must be **direct-dispatched** because the `mol-focus-review` formula is broken.
