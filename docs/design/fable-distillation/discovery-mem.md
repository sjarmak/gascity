## 1. Project shape

`mem` is a **research benchmark** with a scientific thesis, not a product: it turns a multi-agent orchestrator's own audit — the Gas City dolt bead spine (6,691 work records across 18 rigs) plus 874 resolved agent-session transcripts — into a queryable **work-audit graph**, then **benchmarks whether retained/retrieved memory measurably improves future agent work** (success rate, iterations, cost) and which retention/retrieval strategies win. It is two halves under one repo:

- **The store builder (`src/`, TypeScript, ~5,500 LOC, 43 test files, schema v11).** Ingest → parse → store → retrieve → distill, exposed through the `mem` CLI (`bin/mem` → `dist/main.js` → `src/cli/`). Produces the gitignored SQLite+FTS5 sidecar `.mem/store.db`.
- **The eval harness (`memory-bench/`, Python ≥3.12, 157 test files).** Replays held-out tasks under three memory conditions on **Harbor** (a containerized execution substrate, harbor-framework/harbor, Apache-2.0) and reads the gaps between them.

- **The central deliverable, stated in the project's own words:** a benchmark whose numbers _survive a skeptic_ — where "survive a skeptic" resolves concretely to **oracle soundness** (no task counts until its gold diff reproduces AND an empty diff fails) plus **paired per-task deltas with bootstrap CIs that exclude zero**. Everything load-bearing hangs off eval validity: temporal leave-one-out leak-safety, the precision/injected-volume guard, and the ZFC boundary between mechanical signal and model judgment.
- **The load-bearing scientific finding (this is the project's current headline reality).** This real, **direct-to-main** corpus is _signal-poor and largely non-replayable_. Every record's base branch is `main` (there is no PR/CI workflow to link — roughly 1 external ref in 6,000 records), so a merged-PR/CI outcome oracle is **inapplicable by construction** (Decisions 17/18). The headline metric was re-based to an **ablation score-vs-information curve** (the agent is its own control across an information ladder — env- and label-independent). On the real corpus the graded 3-arm result is a **diagnosed-ceiling null**: `ours` **+0.000**, `builtin` +0.125, with only **8 of 407** commit-linkage-recovered oracles scorable — N is bound by replay/oracle fidelity, not by method. The live frontier is a parallel **synthetic-world track** (NeMo-surfaced, code-authored, seed-reproducible) that produced the **first measurable lift** (cross-task continuity 0.062 isolated → 0.188 shared store) plus live Confusion/Staleness retrieval-quality metrics.
- **Who runs it:** effectively a **solo human maintainer (Stephanie / sjarmak, 511 of 511 commits — 508 "sjarmak" + 3 "Stephanie Jarmak") plus a Gas City agent fleet** driving the rig via beads and worktrees. `main` is squash-merged (394 commits); the real history lives in ~200 `mem-*` branches and in the bead store. The "retiring fellow" here is the accumulated **eval-validity discipline** — held across Stephanie's rulings in `docs/architecture-decisions.md` (24 numbered Decisions), the weekly `.gc-reports` audits, and the settled-negative docs — knowledge that lives in bead threads and design docs, not in the squashed `main`.
- **Docs of record:** `README.md` (thesis, pipeline, store-building), `ARCHITECTURE.md`, `docs/architecture-decisions.md` (the Decision ledger), `.gc/memory-eval-harness-spec.md` (the governing spec — **where the log and the spec conflict, the spec governs**), `memory-bench/README.md` (arms + eval modes), `architecture/exports/orient.md` (LikeC4-derived subsystem map, regenerated daily), plus ~40 `docs/mem-*.md` status/gate/null docs and `docs/audits/`.

## 2. Build / test / CI reality

**CI (`.github/workflows/ci.yml`) is the real bar, and it is two independent jobs — one per language.** There is no `make`; each half runs its own project's gate.

- **`python` job** (working-directory `memory-bench/`, Python 3.12): `pip install -e ".[dev]"` → `ruff check membench tests` → `black --check membench tests` → `mypy --strict membench` → `pytest -q`.
- **`typescript` job** (Node 20): `npm ci` → `npm run check` = `tsc --noEmit && eslint src tests && prettier --check && vitest --run`.
- **`.pre-commit-config.yaml` mirrors CI** as local hooks (`cd memory-bench && black/ruff/mypy`; root `npm run typecheck && lint && format:check`) so the rules live in exactly one place (pyproject / package.json). A second workflow, `likec4-pages.yml`, auto-deploys the architecture page.

**Verified traps for a Sonnet-class newcomer:**

1. **`./bin/mem` runs `dist/`, not `src/` — edit TS without `npm run build` and the CLI silently runs stale compiled code** (`bin/mem:3` imports `../dist/main.js`). Build first, always.
2. **`--with-traces` / `mem ingest-traces` needs the gas-city cwd and fails SILENTLY (exit 0, zero traces) from the wrong dir.** `src/ingest/trace-resolve.ts` shells `gc session logs`, which loads `city.toml` from the working directory; run full rebuilds from `/home/ds/gas-city` with an absolute `--store` path, then verify `trace_path`/`repo`/`base_commit` counts before swapping the store into place. A missing `city.toml` resolves zero traces with no error (a missing `gc` binary DOES propagate — deliberate distinction).
3. **`node dist/main.js` alone does nothing** — `main.ts` only defines the function; the entrypoint is `./bin/mem`.
4. **No in-place schema migration.** `SCHEMA_VERSION = 11` (`src/store/schema.ts:28`); `openStore` throws on any other `user_version`. A version bump means rebuilding from the spine via `mem rebuild`, which round-trips the three non-regenerable tables (see §5).
5. **The two languages have two separate dependency worlds** — root `npm ci` (better-sqlite3, zod) vs `memory-bench/` `pip install -e ".[dev]"`. `mypy --strict` is enforced on `membench` (not tests); `black` is the sole Python formatter (ruff lints, never formats — they are configured not to fight, pyproject comment).
6. **Optional-dep test skips are by design, not failures.** Harbor, `data_designer` (NeMo), and every third-party memory SDK (mem0/agentic_memory/nat/graphiti_core/sentence_transformers) are lazily imported and `pytest.importorskip`-gated; CI runs the competitive arms against deterministic fakes (`tests/semantic_fakes.py`) so no paid API or GPU is needed. `ours` integration tests skip gracefully without the TS `dist/` build.
7. **Zero-links guard asymmetry.** `checkRecordLinks` (`src/cli/commands/build-store.ts:118`) throws on a full-corpus build with zero `record_links` but only warns on a single `--rig` build — a broken dependency ingest on a `--rig` build will not fail loudly.

The recurring-rebuild path is `mem ingest-traces` (= `build-store --with-traces --with-provenance` + a before/after coverage diff); `mem coverage` prints the same report read-only. `.mem/store.db` is a rebuildable projection — a mid-build failure aborts loudly and leaves a partial store, which is fine (re-run).
