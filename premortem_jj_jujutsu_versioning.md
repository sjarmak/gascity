## 2. Cross-Cutting Themes (multi-lens convergence = highest-confidence risks)

**Theme A — "Read-only in gc code" ≠ "read-only on disk" (lenses 1, 2, 3, 4).** Four of five lenses independently failed on the same fact: `jj git init --colocate` + per-command auto-`git import`/`export` mutates the shared git backend on every jj invocation. The PRD's defense is *procedural* (place the rig away from polecat/dolt FS), and every lens showed that procedural barrier dissolving ("since it's already provisioned", "test under realistic load"). This is the single highest-confidence risk in the registry. Combined exploit: silent agent-work loss + git-backend corruption that the kill-switch *by construction does not repair* (it only forgets jj, leaving the damaged `.git`).

**Theme B — The gates test the wrong thing / aren't standing (lenses 1, 2, 4).** Gate 1 (concurrency soak) as written can pass on a quiescent tree without ever interleaving gc-core's `git stash -u` against jj auto-snapshot; "`jj debug reindex` recovers" was read as pass when it recovers jj op-log but NOT orphaned git refs. Gate 2 (template stability) was a one-time manual check, not standing CI. R1's security regression test was deferred. Pattern: the safeguards exist on paper but are not mechanically enforced, so they degrade silently.

**Theme C — Deferred maintenance + fail-open defaults reproduce known incidents (lens 3, echoed by 1).** R8 (GC cadence) deferred and R3 (reaper) failing open re-create the two worst incidents already in this workspace's memory: dolt-store-bloat SIGKILL-teardown and oomd-kills-mayor. The premortem didn't invent these — they're documented as having already happened here via a different store.

**Theme D — Sandbox promotion (lenses 4, 5, 1, 2).** Multiple lenses show the "throwaway non-shipping spike" silently becoming standing infrastructure / getting push authority / getting a second co-resident rig. The "sandbox" status is an intention, not an enforced invariant.

## 3. Mitigation Priority List (by failure-modes-addressed × severity, then cost)

1. **[addresses #1,#2,#3,#4 — Critical] Structural read-only overlay.** Do NOT colocate jj on a live gc/polecat-writable dir. Feed a non-colocated jj repo (or clone) from periodic out-of-band `git import` off a read replica. Severs the 3rd-writer problem at the root. Cost: Medium-High. **This is the design's make-or-break change.**
2. **[#1,#2 — Critical] Fix Gate 1 to test the real interleaving + require git-ref recovery.** Drive concurrent polecat-commit + gc-core stash/pop + jj auto-snapshot with dolt refs present; assert stash-pop integrity + zero orphaned git objects; partial reindex = FAIL. Cost: Low.
3. **[#4 — Critical] Make Phase-0 fixes jj-PROOF.** R1 regression test non-deferrable + fail-closed default on unknown push verb; R2 scans auto-snapshotted/untracked content with an untracked-secret acceptance test. Treat the ship-gate hook as security-critical code. Cost: Low-Medium.
4. **[#3 — Critical] Pull R8 forward; R3 fails closed; reconciler jj-aware.** Unconditional `jj util gc` nightly order + `.jj` size budget alert in Phase 1; reaper treats unknown/errored emptiness as live; kill-switch tested under a bloated op-store. Cost: Low.
5. **[#4,#5,#1 — High+] Structural sandbox invariants.** `vcs="jj"` rig provisioning blocks any push remote + any real bead; dashboard route watermarked "SANDBOX — NOT PRODUCTION"; downstream work forbidden while any gate is red; a rendering demo is explicitly NOT gate evidence. Cost: Low.
6. **[#5 — High] De-risk scope before spending.** Promote "ship Phase 0 and stop" to the recommended default; gate Phase 1 entry on a *filed* incident attributable to missing durable change-history/visualization; ask upstream "would you accept any jj mode?" BEFORE writing R4's dual-mode seams; attach an opportunity-cost ledger (dolt-GC / supervisor-recovery / claim-race-nudger). Cost: Low.
7. **[#2 — Critical] Enforce the jj dependency contract.** OS-level digest/Nix pin + `jj --version` startup/CI drift gate; schema-validating parser; dependency-watch order on the `jj-vcs/jj` changelog. Cost: Medium.

## 4. Design Modification Recommendations (top 5)

1. **Replace colocated read-overlay with a non-colocated / clone-fed jj repo.** Addresses #1,#2,#3,#4. Effort: Medium-High. Without this, the kill-switch cannot repair the damage class the design creates.
2. **Sequence the upstream go/no-go FIRST and default to Phase-0-and-stop.** Addresses #5. Effort: Low. A cheap upstream "no" ends the project before any fork-divergence cost is incurred.
3. **Rewrite Gate 1 + Gate 2 as standing, correctly-scoped CI gates; make every safety test non-deferrable.** Addresses #1,#2,#4. Effort: Low-Medium.
4. **Pull R8 (GC cadence) into Phase 1 and flip R3 to fail-closed.** Addresses #3. Effort: Low.
5. **Make "sandbox" a structurally-enforced state (no push remote, no real bead, watermarked, gate-red blocks downstream).** Addresses #4,#5,#1. Effort: Low.

## 5. Full Failure Narratives

(Preserved verbatim from each lens — see the five sections below.)

### Lens 1 — Technical Architecture
Phase 0 + Phase 1 shipped; green demos were misread as Gate 5 satisfaction; a 2nd jj rig was let co-resident with a live polecat pool "to test under load," dissolving the procedural isolation. gc-core's `git stash push -u` (`git.go:215`) raced jj auto-snapshot → `git stash pop` replayed onto a jj-rewritten tree → phantom conflicts + hard reset ate stashes. Porcelain read clean (work in working-copy commit), so the reaper deleted live worktrees. Soak had passed because it tested a quiescent tree with no stash/pop interleaving and no dolt refs. Backend wedged; `jj debug reindex` recovered op-log but not orphaned git objects; R7 change-IDs no longer resolved → beads claimed-but-unroutable → nudger re-nudged → double-claim got worse. Kill-switch worked but damage was in the shared git backend it doesn't touch. **Root cause:** read-overlay premised on read-only-in-code-path implying read-only-on-disk, with procedural (not structural) isolation. **Severity: Critical, Likelihood: High.**

### Lens 2 — Integration & Dependency
jj pinned at v0.28 "in the PRD" but never locked at OS level; a `brew upgrade` to v0.31 (during a dashboard toolchain bump) renamed template builtins and changed `parents` shape. The `git.ts`-modeled parser (no boundary validation) parsed `change_id` as `undefined` → d3-dag null keys → React white-screen, 2 days to trace. Meanwhile rtk's git-literal rewrite let agents' raw-`git` reflex bypass both the token proxy and the colocation isolation; a raw `git` + jj auto-import + gc-core stash collision corrupted the colocated backend, `jj debug reindex` left dangling refs; only the sandbox prevented data loss. **Root cause:** "pin + own the template" was a prose intention, not an enforced lock + validating parser; rtk git-literacy + agent git-reflex (Open Q#5) left open. **Severity: Critical, Likelihood: High.**

### Lens 3 — Operational
R3's jj-aware reaper shelled `jj log` during an in-flight auto-`git import`; non-zero exit read as "no work" → reaped 2 live worktrees (no reflog salvage under jj). R8 deferred → unbounded `.jj` op-store growth on a standing spike rig → climbing `git import` latency → supervisor reconciler health-probe timeout → drain/recreate loop against an existing `.jj` → dangling workspace; mid-incident kill-switch `jj workspace forget` blocked on the bloated store, half-removed `.jj`; cumulative pressure → systemd-oomd killed the mayor as collateral (documented prior pattern). **Root cause:** GC cadence (R8) deferred + reaper fail-open (R3) on a long-lived rig. **Severity: Critical, Likelihood: High.**

### Lens 4 — Scope & Requirements
Phase 0 shipped clean (2 fixes merged upstream on merit) — that win manufactured momentum past the opportunity-cost bar the PRD's own dissent had already failed it against ("jj fixes none of the named pains"). 4 months of dashboard-viz work while dolt-GC, supervisor-recovery, and the routed-bead-nudger double-claim root cause went unaddressed. Sandbox screenshot looked prod-ready → "why isn't this on the live dashboard?" → "optional" eroded toward "turn it on for gascity" while Gate 1 stayed red. Upstream bounced the dual-VCS mode as unrequested scope creep → permanent fork divergence carrying `gcsync` rebase cost. **Root cause:** built elegant tech no logged incident demanded; Phase-0 win + demo skated past opportunity-cost dissent. **Severity: High, Likelihood: High.**

### Lens 5 — Security & Compliance
R1 regex shipped WITHOUT its required unit test (deferred, never slung). 4 months later a "simplify" refactor changed the pattern to `^(git|jj)\s+push` — which doesn't match `jj git push` — silent regress, CI green (no test). Spike rig got a fork remote + a real bead ("already provisioned"); a polecat ran `jj git push --remote fork`; regressed gate waved it through; mayor-only publish boundary (git-shaped hook) routed around; change hit a public `gastownhall/gascity` PR with no `/gascity-ship` sentinel. gitleaks no-op'd: auto-snapshot had folded an untracked `~/.claude-homes` account token into the working-copy commit before `jj diff` was taken, so "files scanned > 0" yet the secret was excluded. Credential live ~40 min on a public PR. **Root cause:** ship gate + gitleaks made jj-aware but not jj-proof (untested regex → silent regress; diff scanned after snapshot swallowed the untracked secret) + spike rig given push authority. **Severity: Critical, Likelihood: High.**
